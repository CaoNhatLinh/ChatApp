# C2 cyclic timeout and latest-state publication — 2026-10-20

## Scope and status

Connected implementation, controlled verification only. The persistent feature
roadmap is **not complete**. Docker installation remains deferred by the user.
No engine install/probe, database reset, provider write, tunnel, commit or push
was performed in this slice. Existing unrelated worktree changes were preserved.

## Behavior and changed files

- `chat-service/src/main/java/com/chatapp/chat_service/canonical/call/CallWorkRepository.java`
  and `CassandraCallWorkRepository.java`: 16 fixed pending-work shards, full five-key
  bounded paging, exact removal, durable CAS checkpoint and wrap. No hourly lookback.
- `CallRepository.java` / `CassandraCallRepository.java` in that package: prewrite
  PUBLISH for every mutation, EXPIRE for nonterminal mutations; exact-revision
  publication receipt and slot-only CAS fence preserving active call identity.
  Removed hourly queue preparation/consumer methods, not an old-format fallback.
- `CallTimeoutWorker.java`: scheduled bounded traversal; retain failed work while
  advancing the cursor, revisit on wrap, fence missing candidates after their
  producer deadline, expire authoritative overdue states. A snapshot/slot read
  straddling a candidate commit must retain its work, not delete it as an orphan.
- `CallStatePublisher.java`: recheck current authority, STATE broker handoff, then
  exact-revision/previous-receipt CAS. At-least-once latest-state convergence,
  not every transition, exactly-once delivery or subscriber acknowledgement.
- `CallSignalingService.java`: controls use the same publisher as recovery;
  SIGNAL stays ephemeral with authenticated actor/peer and bounded SDP/ICE.
- `chat_app_complete.cql`: canonical fresh schema replaces hourly discovery with
  work/checkpoint tables; authority adds `published_version`. No live migration.
- `chat-service/src/main/resources/application.properties` and `.env.example`:
  explicit poll delay/batch defaults; batch is clamped to 1..100 per shard.
- `chatapp_frontend/src/features/calls/types.ts` and `hooks/useWebRtcCall.ts`:
  one STATE/SIGNAL discriminated contract, validated authority participants,
  version guards and actorless system-terminal handling. Retired START/JOIN/END
  topic shapes are not accepted; command/private-result action names are unchanged.
- `docs/api/asyncapi.yaml`: both event variants with declared required fields.
- Backend tests: `CassandraCallRepositoryTest`, `CassandraCallWorkRepositoryTest`,
  `CallRecoveryTest`, `CallLifecycleServiceTest`, `CallLifecycleCassandraIT`,
  `CallControllerTest`, `InfrastructureManifestTest`; updated bindings, failure/
  receipt/fencing/cursor tests and contract parity. Opt-in IT compiles but is unrun.
- `chatapp_frontend/scripts/call-browser-smoke.mjs`: actorless timeout and retired
  contract rejection added to existing call/media/command regression scenarios.
- `scripts/test-local-schema.ps1`, `docs/SCHEMA_CONSOLIDATION.md`, ADRs 0017/0018,
  `tasks/call-lifecycle-contract.md`, transport report and `tasks/todo.md`: current
  schema/behavior, rationale, evidence boundary and remaining gates.

## Open acceptance and product work

Live conditional CQL parsing/atomicity, competing drivers, kill/restart at every
prewrite/authority/handoff/receipt/checkpoint boundary, real broker receipt failure,
backlog/tombstone/compaction/partition-size load tests and real two-browser media
remain open. LIMIT bounds returned rows, not tombstones scanned. Fixed shards do
not imply unlimited throughput or a hard timeout SLA. No unsafe TTL/gc tuning.

Global incoming-call discovery, reload-time active-call lookup and C3 authorized
history/participants UI remain unimplemented. The hook still observes the active
DM only. Media lifecycle, settings, email and moderation remain on the full roadmap.
