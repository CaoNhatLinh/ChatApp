# UI audit, 30 August 2026

## Evidence

The visual audit is captured at runtime with deterministic browser fixtures,
not production user data. The capture script is
`chatapp_frontend/scripts/visual-audit-capture.mjs`; outputs are ignored under
`chatapp_frontend/artifacts/ui-audit/current`.

It covers desktop and mobile for public, auth, recovery, invite, product,
community, profile and settings routes. It records route status, console errors
and horizontal overflow with every capture.

The authenticated workspace audit covers both no-selection and selected-room
states. The selected-room fixture includes a canonical conversation and message
so header actions, room visual treatment, message history and composer are
inspected together rather than inferred from an empty canvas.

## Findings before the redesign increment

- The public home used a generic product render and a familiar three-column
  feature grid. It did not establish an ownable product identity.
- Help had a large amount of empty space followed by two competing text-heavy
  columns. A user had to scan content before knowing the next action.
- Community discovery surfaced too many equal metadata chips and cards at once.
- Notification settings repeated nested surface treatments and exposed every
  detail at the same priority.
- The mobile messenger opened the navigation drawer over an otherwise empty
  canvas. It needs a compact, conversation-first mobile state.
- The first dark workspace pass only checked the no-selection state. In a
  selected room the inherited light header and theme overlays made text faint,
  and mobile exposed duplicate list navigation plus unavailable calling
  controls.

## Decisions

- The product owns a standalone Connection Paths logo and favicon. The supplied
  personal logo remains separate.
- Landing uses one editorial hero image with a clear job: establish the brand
  before the product UI begins. Generated imagery will not fill routine product
  screens.
- Product, admin and settings redesign will use progressive disclosure. A
  screen shows the task, current state and primary action first; details appear
  only when the user asks for them.
- The first implementation increment replaces the landing hero and logo.
- Help now promotes one next action and keeps answers in native disclosure.
- Notification settings now group delivery choices as rows, and quiet hours are
  disclosed only when relevant. Page-mode settings now use the intended desktop
  two-column workspace instead of stacking navigation above content.
- On mobile, the first-use messenger conversation list fills the viewport before
  a conversation is selected; after selection it remains a drawer.
- Messenger is now a deliberate dark operational surface: a compact dark
  conversation rail, ink-based message canvas, restrained orange current-state
  accents, and a dedicated dark composer dock. Room presets use deterministic
  dark overlays instead of deriving colors from whichever page theme encloses
  the workspace. This prevents a selected room from reverting to a light shell.
- The global authenticated header and chat sidebar no longer repeat the app
  logo. Mobile uses one list button as its return path. Group rooms omit
  unavailable voice/video controls, and the room-theme control stays off the
  narrow header so the primary title, search and context action remain legible.
- Composer actions now follow a deliberate two-level model. File attachment,
  emoji and send remain immediate. Photo/video attachment and poll creation
  are direct on larger screens and move to the labelled **Tùy chọn khác** menu
  on mobile; live call appears only for a 1:1 conversation. This preserves
  capability without treating every optional action as equal to typing.
- `public/noi-default-avatar.webp` is the generated non-human default profile
  mascot. Product fallbacks use it instead of initials in the chat sidebar,
  conversation list, contacts, profile/settings, member directory, mentions,
  room creation and message sender states.
- Community discovery now presents a compact, paginated scan list. Full filter
  controls are disclosed rather than occupying every result row.
- The profile now uses one identity rail plus a single information flow. Account
  fields and shortcuts are scan rows rather than multiple equal-weight cards.
- The global admin sanction form is disclosed independently of the report queue.
  Other admin operator panels remain follow-up redesign targets.

## External content dependency

Privacy and terms layouts are implemented, but production legal copy cannot be
certified from repository code. It requires an approved legal source covering
the operating entity, applicable jurisdiction, retention, processors, contact
route and effective date. Those pages must not be represented as legal advice
or production-approved policy until that source is supplied.
